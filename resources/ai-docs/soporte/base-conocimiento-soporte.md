# Base de conocimiento de soporte AEME Group

Esta base resume patrones recurrentes observados en el histórico real de WhatsApp. Debe usarse para adaptar cada respuesta al caso concreto, no para copiar textos literalmente. Las líneas rojas de las instrucciones del agente prevalecen siempre sobre cualquier práctica histórica.

## Prioridad aproximada de los temas observados

1. Menús y buffet: cambios automáticos, forzados, ruedas, servicios y platos.
2. Acceso a la aplicación, usuarios y problemas para entrar.
3. Pilas, etiquetas sin respuesta y comprobaciones de alimentación.
4. Antenas, repetidores, cobertura y etiquetas con poca señal.
5. Cambios de posición, sustitución y vinculación de etiquetas.
6. Pantallas congeladas, dañadas o con contenido incorrecto.
7. Etiquetas que no se actualizan o tardan demasiado.
8. Traducciones, idiomas y alérgenos.
9. Exportaciones, listados y documentación.
10. Material, recambios y garantías.

## 1. Una o varias etiquetas no se actualizan

**Datos que conviene pedir**
- Hotel o sede, buffet o zona y servicio afectado.
- Posición de cada etiqueta y código de barras, preferiblemente con foto legible.
- Si falla una etiqueta, varias de una zona o toda la instalación.
- Qué cambio se esperaba y desde cuándo.
- Si se probó un forzado y qué ocurrió.
- Si la etiqueta está en su posición habitual y cerca de la cobertura normal.

**Criterio de diagnóstico**
- Una sola etiqueta: comprobar identificación, alimentación, posición y cobertura.
- Varias de la misma zona: sospechar cobertura o incidencia común y escalar para revisión remota.
- Todas las etiquetas o todo un servicio: tratarlo como posible incidencia general y escalar.
- Si el cambio aparece en la aplicación pero no en la etiqueta: confirmar posición, código y cobertura antes de pedir un nuevo forzado.

**Respuesta tipo adaptable**
«Para revisarlo necesito confirmar si afecta solo a esta etiqueta o también a otras de la misma zona. Envíeme, por favor, una foto donde se vea el código de barras, la posición y el cambio que debería mostrar. Indíqueme también si ya ha forzado el menú y qué resultado obtuvo. Con esos datos podremos revisar el caso y, si corresponde, forzar la actualización desde soporte.»

**Después de una actuación remota confirmada por soporte**
«Hemos solicitado una nueva actualización de la etiqueta [código/posición]. ¿Puede confirmarnos si ya muestra el contenido correcto?»

No afirmes que has forzado o corregido nada si el entorno no confirma que esa acción se realizó.

## 2. El menú de desayuno, comida o cena no cambia automáticamente

**Datos que conviene pedir**
- Hotel, buffet y servicio afectado.
- Menú o rueda que debería estar activa y la que aparece.
- Si el fallo ocurrió una vez o se repite.
- Si el cliente hizo un cambio momentáneo o un forzado manual.
- Si afecta a todas las etiquetas o solo a algunas.

**Solución habitual**
- Diferenciar un fallo de programación del menú de un fallo de actualización de etiquetas.
- Si el cliente necesita resolver el servicio actual, indicar el forzado de menú solo cuando el procedimiento esté documentado para ese cliente.
- Escalar para revisar la programación automática si el menú incorrecto reaparece en el siguiente servicio.

**Respuesta tipo adaptable**
«Para distinguir si falla la programación o la actualización de las etiquetas, indíqueme qué menú debería aparecer, cuál aparece ahora y si afecta a todo el buffet. ¿Ha realizado un forzado del servicio? Si lo ha hecho, confirme si las etiquetas cambiaron. Revisaremos también la programación para evitar que vuelva a ocurrir en el próximo servicio.»

## 3. El cliente quiere forzar un menú o una actualización

**Antes de orientar**
- Confirmar hotel, buffet, servicio y menú que se quiere mostrar.
- Aclarar si es un cambio puntual o si debe mantenerse en la programación automática.
- No confundir «forzar ahora» con «cambiar la rueda o calendario futuro».

**Respuesta tipo adaptable**
«¿Quiere mostrar ese menú solo en el servicio actual o dejarlo programado para los próximos días? Indíqueme el buffet, el servicio y el menú exacto. Si es un cambio puntual, podrá forzarse para el servicio actual; si debe repetirse, tendrá que revisarse la programación.»

## 4. Faltan platos, se han borrado menús o aparece contenido incorrecto

**Datos que conviene pedir**
- Nombre del hotel, buffet, rueda y menú.
- Platos concretos que faltan o contenido que aparece por error.
- Captura o foto del resultado actual.
- Momento aproximado en que se detectó el cambio.

**Solución habitual**
- Pedir una lista concreta; no responder solo «lo revisamos».
- Distinguir entre plato borrado, plato no validado, posición sin asignar y menú equivocado.
- Si la restauración o edición requiere acceso interno, escalar con el inventario exacto.

**Respuesta tipo adaptable**
«Para recuperar el contenido correcto necesito que me indique la rueda y el menú afectados, junto con los platos que faltan o aparecen incorrectamente. Si puede, adjunte una captura o foto. Con esa lista podremos comprobar si se trata de platos eliminados, sin validar o asignados a otro menú.»

## 5. Copiar, duplicar o cambiar una rueda de menús

**Datos que conviene pedir**
- Menú de origen y destino.
- Qué servicios y días debe cubrir.
- Si deben copiarse también posiciones, traducciones y alérgenos.
- Fecha a partir de la cual debe aplicarse.

**Respuesta tipo adaptable**
«Indíqueme qué menú desea usar como origen, cuál será el destino y desde qué fecha debe aplicarse. Confirme también si deben conservarse las mismas posiciones, traducciones y alérgenos. Así evitaremos copiar solo los platos y dejar incompleta la configuración.»

## 6. Cambiar una etiqueta de posición o sustituir una etiqueta averiada

**Formato requerido**
Solicitar cada cambio como `código de la etiqueta nueva - posición de destino`.

**Datos que conviene pedir**
- Hotel o sede.
- Código de barras completo de la etiqueta nueva.
- Posición exacta de destino.
- Foto de la etiqueta si el código no es inequívoco.
- Si la posición contiene una o varias divisiones.

**Respuesta tipo adaptable**
«Envíeme los cambios en formato `código - posición`, uno por línea, e indique el hotel. Si alguna posición está dividida en varias partes, señale también la división exacta. Cuando se haya realizado el cambio, habrá que comprobar que cada etiqueta muestra el contenido correspondiente.»

**Regla especial**
Las etiquetas de 7,5 pulgadas las cambia AEME Group. No indiques al cliente que haga esa configuración.

## 7. Etiqueta bloqueada o con imagen congelada

**Datos que conviene pedir**
- Posición y código de barras.
- Foto del frontal y del código.
- Si cambió alguna vez tras un forzado.
- Si otras etiquetas de la zona funcionan.
- Estado de las pilas y modelo de etiqueta.

**Solución habitual**
- No asumir que «bloqueada» significa avería física: puede ser contenido congelado, baja batería, poca señal o una incidencia común.
- Pedir identificación y contexto antes de escalar o sustituir.

**Respuesta tipo adaptable**
«Para saber si está bloqueada, sin alimentación o sin cobertura, envíeme una foto de la pantalla y otra donde se vea el código de barras. Indíqueme la posición, el modelo y si otras etiquetas cercanas se actualizan. Si ya cambió las pilas, dígame qué pila utilizó y si la etiqueta reaccionó después.»

## 8. Pilas agotadas o etiqueta que sigue sin funcionar tras cambiarlas

**Referencias conocidas**
- Referencia interna: `AM-BZ2450`; equivalente: `CR2450`.
- Marcas compatibles: Beidongli, HenliMax y NSN.
- VARTA no es compatible.
- Modelos individuales: `ZKC42V`.
- Modelos de 4 y 7,5 pulgadas: `ZKC75V-NL`.

**Comprobación habitual**
- Confirmar el modelo antes de recomendar una referencia.
- Verificar que la pila sea del tipo y grosor correctos.
- Si se puede hacer de forma segura, comparar con pilas funcionales de otra etiqueta del mismo modelo.
- Tras el cambio, identificar la etiqueta, situarla en su ubicación habitual con cobertura y solicitar a soporte un nuevo intento de actualización.

**Respuesta tipo adaptable**
«Antes de confirmar la pila necesito saber el modelo de la etiqueta. Envíeme una foto del frontal y del código. Si ya la ha sustituido, confirme la marca y referencia utilizadas. Después del cambio, deje la etiqueta en su posición habitual y avísenos para que soporte revise su estado y solicite una actualización.»

**Línea roja**
No tramites pilas ni recambios. Para pedir material, indica que escriban a `postventa@aemegroup.com` con material, cantidad y foto de referencia.

## 9. Antena o repetidor desconectado, o etiquetas con poca señal

**Datos que conviene pedir**
- Hotel, zona o buffet afectado.
- Cuántas etiquetas fallan y si están concentradas en una zona.
- Desde cuándo ocurre.
- Foto o ubicación aproximada de las etiquetas afectadas, si ayuda a determinar cobertura.

**Solución segura**
- El cliente no debe reiniciar, desconectar, reconectar, manipular ni cambiar cables de la antena o repetidor.
- Escalar al equipo de soporte para revisión remota.
- Se puede pedir al cliente que deje las etiquetas en su posición habitual o que confirme si otras etiquetas cercanas funcionan, pero no que manipule infraestructura.

**Respuesta tipo adaptable**
«Parece que puede tratarse de un problema de cobertura o de la antena de esa zona. No reinicie ni manipule la antena o el repetidor. Indíqueme el hotel, la zona afectada, desde cuándo ocurre y si fallan todas las etiquetas o solo algunas. El equipo de soporte revisará la conectividad.»

## 10. Traducciones o idiomas que faltan o son incorrectos

**Datos que conviene pedir**
- Qué idiomas o traducciones tiene configurados actualmente la etiqueta; nunca asumirlos.
- Plato, posición y texto correcto en cada idioma.
- Foto del contenido actual.
- Si el plato está validado y de dónde procede la traducción, cuando el cliente lo sepa.

**Respuesta tipo adaptable**
«¿Qué traducciones tiene configuradas esa etiqueta y cuál debería mostrarse en cada idioma? Envíeme la posición, el plato y el texto correcto, junto con una foto del resultado actual. Así podremos comprobar si falta la traducción, si no está validada o si la etiqueta no ha recibido el cambio.»

## 11. Alérgenos que faltan o se muestran mal

**Datos que conviene pedir**
- Plato y menú afectados.
- Alérgenos correctos.
- Fuente o ficha desde la que deberían recibirse.
- Captura o foto de lo mostrado.
- Si el plato está validado.

**Respuesta tipo adaptable**
«Indíqueme el plato, el menú y los alérgenos que deberían aparecer. Adjunte una captura o foto y confirme, si lo sabe, si el plato está validado en la fuente de datos. Con ello podremos distinguir entre un dato incompleto y un problema de actualización de la etiqueta.»

## 12. No puede entrar en la aplicación o la contraseña no funciona

**Datos que conviene pedir**
- Hotel o sede.
- Dirección web exacta que está usando.
- Usuario o correo, sin pedir que envíe la contraseña.
- Captura del error.
- Si antes podía acceder y desde qué dispositivo.

**Solución habitual**
- Confirmar primero que usa el portal correcto.
- Verificar si se trata de credenciales existentes, alta de un nuevo usuario o permisos insuficientes.
- Escalar cualquier recuperación o creación que requiera intervención interna.

**Respuesta tipo adaptable**
«Envíeme la dirección web exacta desde la que intenta acceder, el usuario o correo y una captura del error. No envíe su contraseña. Indíqueme también si antes podía entrar y desde qué dispositivo. Así podremos comprobar si está usando el portal correcto o si es necesario revisar el usuario y sus permisos.»

## 13. Crear usuarios o cambiar permisos

**Datos que conviene pedir**
- Nombre, correo, hotel o sede y función de la persona.
- Qué acciones debe poder realizar: cambios momentáneos, gestión de rueda, edición u otras.
- No generar ni compartir contraseñas en el borrador salvo que exista un procedimiento seguro y autorizado fuera del agente.

**Respuesta tipo adaptable**
«Para solicitar el acceso, indíqueme nombre, correo, hotel y qué tareas debe poder realizar. Un agente humano revisará el alta o los permisos y facilitará el acceso por el canal autorizado.»

## 14. Pantalla dañada, con líneas, manchas, líquido o rotura

**Datos que conviene pedir**
- Foto frontal clara y foto del código de barras.
- Modelo, posición y cuándo apareció el daño.
- Si el contenido cambia parcialmente o permanece congelado.
- Si hubo golpe, humedad o líquido, sin acusar ni concluir una causa.

**Respuesta tipo adaptable**
«Envíeme una foto frontal donde se vea el defecto y otra del código de barras. Indíqueme el modelo, la posición y si la pantalla aún cambia de contenido. Con esa información un agente humano podrá determinar si es una incidencia técnica o si debe revisarse como posible daño físico.»

Si el caso implica garantía, no dictamines cobertura ni condiciones; escálalo a un humano.

## 15. Etiquetas divididas o configuraciones especiales

**Casos habituales**
- Una etiqueta muestra dos o más platos.
- Posiciones con sufijos o divisiones.
- Plantillas especiales, iconos o información adicional.
- Etiquetas de 7,5 pulgadas.

**Respuesta tipo adaptable**
«Al tratarse de una etiqueta dividida o una plantilla especial, necesito la posición completa, el código de la etiqueta y cómo debe repartirse el contenido en cada zona. Adjunte una foto o esquema. Este tipo de configuración debe revisarlo AEME Group antes de aplicarlo.»

## 16. Farmacias: precios o etiquetas que no se actualizan

**Datos que conviene pedir**
- Farmacia o sede.
- Productos o etiquetas afectados.
- Código de las etiquetas y ejemplos de precio esperado frente al mostrado.
- Desde cuándo ocurre y si afecta a todo el catálogo o a artículos concretos.
- Estado de la integración y disponibilidad para asistencia remota, sin solicitar claves por el chat.

**Respuesta tipo adaptable**
«Indíqueme la farmacia, los productos afectados y un ejemplo del precio esperado frente al que aparece. Envíeme también el código de las etiquetas. Como la actualización depende de la integración, el equipo de soporte deberá revisar la sincronización y valorar una sesión remota mediante AnyDesk.»

No confundas una consulta sobre precios mostrados en etiquetas con una solicitud comercial: puedes diagnosticar el dato mostrado, pero nunca dar tarifas, presupuestos o precios de los servicios de AEME.

## 17. Exportar menús, platos, alérgenos o listados

**Datos que conviene pedir**
- Hotel, menú o conjunto de datos.
- Formato deseado, si es relevante.
- Si debe incluir traducciones, alérgenos, posiciones u otros campos.
- Destino o correo solo si el procedimiento autorizado lo requiere.

**Respuesta tipo adaptable**
«Indíqueme qué menú o conjunto desea exportar y qué campos debe incluir: platos, posiciones, traducciones, alérgenos u otros. Confirme también el formato que necesita. Si la exportación no está disponible directamente, un agente humano preparará o gestionará el archivo.»

## 18. Solicitud de material, soportes, pinzas, recambios o pilas

**Respuesta tipo obligatoria**
«Para solicitar material, escriba a `postventa@aemegroup.com` indicando el material, la cantidad y adjuntando una foto de referencia.»

No tramites el pedido, no confirmes existencias y no des precios ni plazos.

## 19. Garantías

**Respuesta tipo adaptable**
«Este caso debe revisarlo un agente humano para comprobar las condiciones y el estado del material. Voy a dejar la incidencia preparada para su revisión, sin confirmar todavía si está cubierta por garantía.»

No la envíes automáticamente a un correo, no prometas sustitución y no dictamines cobertura.

## 20. Foto sin código de barras legible

**Indicaciones útiles**
- Pedir una foto frontal y cercana.
- Código completo visible, sin dedos ni objetos.
- Buena luz, sin reflejos y con enfoque.
- Preferiblemente JPEG o PNG si el canal permite controlar el formato.

**Respuesta tipo adaptable**
«No se ha podido leer el código de barras. Envíe otra foto más cercana y frontal, con el código completo, enfocado y sin reflejos ni objetos que lo tapen. Si puede leerlo, también puede escribir el código directamente.»

## 21. El cliente pregunta por el estado de una incidencia o cambio anterior

**Datos que conviene usar**
- Solo el contexto del ticket actual y las actuaciones confirmadas en él.
- No inventar estados, plazos ni acciones realizadas.

**Respuesta tipo adaptable**
«Con la información disponible no puedo confirmar que el cambio se haya completado. Dejo el caso preparado para que el equipo responsable revise el estado y confirme la actuación. Si dispone del número de ticket, posición o código de etiqueta, inclúyalo para localizarlo.»

## Patrón general de respuesta

1. Reconocer el problema concreto en una frase.
2. Usar todos los datos ya disponibles; no volver a pedirlos.
3. Pedir únicamente lo que falta para distinguir las causas plausibles.
4. Dar pasos concretos solo cuando sean seguros y estén respaldados por esta base.
5. Indicar qué confirmación debe aportar el cliente después de la prueba.
6. Escalar con un resumen útil cuando la solución requiera acceso remoto, revisión interna, garantía, antena o conocimiento no documentado.
7. Variar la redacción según el caso. No copiar respuestas genéricas como «lo revisamos» sin una pregunta, acción o siguiente paso concreto.
